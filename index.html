📋 Resumen (300–500 palabras)

NEXA Market es una plataforma web de comercio electrónico desarrollada como Trabajo de Fin de Máster (TFM) en el Máster de Inteligencia Artificial y Big Data de UCAM/Structuralia. El proyecto sigue la metodología CRISP-DM (Chapman et al., 2000; Wirth & Hipp, 2000) adaptada al contexto de un entorno de cliente puro: comprensión del negocio (retail digital con recursos limitados), comprensión de los datos (dataset sintético de 18 productos y 450 transacciones procedurales), modelado, evaluación y despliegue estático.

El sistema integra cinco técnicas de ciencia de datos: (1) filtrado basado en contenido mediante vectorización de 19 dimensiones y similitud coseno con explicabilidad directa; (2) reglas de asociación Apriori sobre las 450 transacciones con umbrales de soporte ≥ 2%, confianza ≥ 25% y lift > 1.05; (3) regresión lineal por mínimos cuadrados sobre serie temporal de 12 semanas para proyectar las 4 siguientes; (4) análisis ABC/Pareto del inventario con clasificación por valor acumulado (regla 80/20); y (5) asistente conversacional NOVA con corrección ortográfica Damerau-Levenshtein y aritmética por shunting-yard sin eval().

El dataset es completamente sintético y generado proceduralmente con semilla fija (seed=20260624), hecho documentado de forma explícita en la interfaz. Esto implica que Apriori reencuentra las correlaciones sembradas — lo que valida la implementación del algoritmo pero no su capacidad de descubrimiento sobre datos independientes. Una línea de trabajo futura prioritaria es la validación con un dataset público (Instacart, UCI Online Retail).

Los resultados cuantitativos se calculan en tiempo real en la Sección 06 del panel. Todo ello se materializa en una interfaz de archivo único desplegable sin infraestructura de servidor, contribuyendo a la democratización del acceso a herramientas de analítica para comercios con recursos limitados.

🔄 Metodología — CRISP-DM

Fase 1
Comprensión del negocio
Problema: pequeños comercios sin acceso a herramientas de analítica e IA. Objetivo: demostrar que técnicas de ciencia de datos pueden implementarse sin infraestructura de servidor.
Fase 2
Comprensión de los datos
Dataset sintético de 18 productos (9 categorías, 8 nutrientes) y 450 transacciones procedurales. Estructura documentada en Sección 08 (esquema SQL + JSON). Limitación explicitada: datos generados con seed fijo.
Fase 3
Preparación de los datos
Vectorización de productos: normalización de precio y kcal, codificación one-hot de categoría (9 dims), codificación multi-hot de nutrientes (8 dims). Vector final: 19 dimensiones por producto.
Fase 4
Modelado
Cinco técnicas implementadas desde cero en JS vanilla: similitud coseno, Apriori, regresión OLS, ABC/Pareto y PLN con Damerau-Levenshtein. Sin uso de librerías externas de ML.
Fase 5
Evaluación
Métricas calculadas en tiempo real: R², MAE, RMSE (regresión); soporte/confianza/lift (Apriori); distribución A/B/C y % Pareto (inventario); cobertura de intenciones (NOVA). Ver Sección 06.
Fase 6
Despliegue
Archivo HTML único autodesplegable en GitHub Pages. Sin dependencias de backend, base de datos o servidor. Accesible desde cualquier dispositivo con navegador moderno.

🇬🇧 Abstract (English)

ABSTRACT — NEXA Market: An AI-Powered Digital Supermarket Prototype NEXA Market is a client-side web prototype developed as a Final Master's Project (TFM) for the Master's in Artificial Intelligence & Big Data at UCAM/Structuralia. The system integrates five data science techniques — content-based filtering (cosine similarity), association rule mining (Apriori), linear regression for demand forecasting, ABC/Pareto inventory analysis, and a rule-based conversational assistant (NOVA) with fuzzy matching via Damerau-Levenshtein distance — into a single deployable HTML file with no backend dependencies. The dataset consists of 18 synthetic product records and 450 procedurally generated transactions. Five interactive Canvas-based visualizations are provided. The prototype demonstrates the feasibility of deploying a fully explainable recommendation and analytics system in a zero-infrastructure environment, with direct applications to small retail businesses with limited technical resources.

Keywords: e-commerce · content-based filtering · cosine similarity · Apriori · association rules · linear regression · ABC analysis · Pareto · NLP · Canvas API · retail AI

⚠️ Limitaciones del prototipo

Dataset sintéticoLas 450 transacciones se generaron proceduralmente con pares predefinidos. Apriori reencuentra correlaciones sembradas, no las descubre.
Sin backend realNo hay base de datos persistente — todo el estado vive en localStorage. Las "compras" son simulaciones académicas sin procesamiento real de pagos.
Escala reducida18 productos y 9 categorías. El comportamiento del recomendador en catálogos de miles de SKUs requeriría validación adicional.
Regresión univariadaEl pronóstico usa solo tiempo como variable independiente. No incorpora estacionalidad, promociones ni variables externas.
NOVA basada en reglasEl asistente no usa un LLM — es un sistema de patrones determinista. El cubrimiento de intenciones fuera del catálogo es limitado.
Validación externaSin A/B testing ni usuarios reales. Las métricas de evaluación (R², cobertura del recomendador) se calculan sobre el mismo dataset de entrenamiento.

Abstract en inglés

ABSTRACT NEXA Market is a client-side web prototype developed as a Final Master's Project for the Master's in Artificial Intelligence and Big Data at UCAM/Structuralia. The system integrates five data science techniques into a single deployable HTML file with no backend dependencies: content-based filtering via cosine similarity (19-dimensional product vectors), association rule mining with the Apriori algorithm (450 synthetic transactions, 28 rules, max lift = 2.49), linear regression demand forecasting (β₁ = +3.73 units/week, R² = 0.79), ABC/Pareto inventory classification (10 Class-A products, 78.1% of inventory value), and a rule-based conversational assistant (NOVA) with Damerau-Levenshtein spelling correction and arithmetic evaluation via the Shunting-Yard algorithm. Data persistence is implemented through Firebase Firestore with an IndexedDB fallback. The dataset consists of 18 synthetic product records and 450 procedurally generated transactions. This prototype demonstrates the feasibility of deploying a fully explainable recommendation and analytics system in a zero-infrastructure environment.

Min-Max para precio y kcal, one-hot para categoría (9 dims), multi-hot para nutrientes (8 dims). Vector final: 19 dimensiones.

Fase 4 · Modelado

5 técnicas implementadas desde cero en JS vanilla: coseno, Apriori, OLS, ABC/Pareto, Damerau-Levenshtein + shunting-yard.

Fase 5 · Evaluación

Métricas calculadas en tiempo real al cargar el prototipo: R², MAE, RMSE, distribución ABC, cobertura NOVA sobre 8 consultas de prueba.

Fase 6 · Despliegue

Archivo HTML único. GitHub Pages. Sin servidor. Firebase Firestore opcional. Accesible desde cualquier dispositivo moderno.

Escalabilidad y relación con Big Data

Recomendador → ANN

Los vectores de 19 dims escalan a catálogos de miles de SKUs. Con n=10.000 productos se reemplaza el scan lineal actual por búsqueda Approximate Nearest Neighbors (FAISS, ScaNN).

Apriori → FP-Growth

Con millones de transacciones reales, FP-Growth (Han et al., 2011) escala donde Apriori no puede. El esquema Firestore implementado soporta esa escala directamente.

OLS → ARIMA / Prophet

Con datos reales la siguiente iteración incorpora estacionalidad y efectos de calendario, críticos en retail (Navidad, Black Friday). El pipeline OLS actual es la línea base.

Firestore → BigQuery

El esquema implementado es compatible con la exportación nativa Firestore → BigQuery de GCP, habilitando SQL analítico sobre el historial completo sin cambiar el frontend.

Limitaciones y líneas futuras

Dataset sintético

Apriori reencuentra pares sembrados. Línea futura: Instacart Market Basket (3M+ órdenes) o UCI Online Retail II.

n=12 para regresión

Serie corta sin estacionalidad. Línea futura: ARIMA o Prophet con variables exógenas (precio, promociones, día).

NOVA basada en reglas

Sin generalización fuera del dominio. Línea futura: LLM (Gemini Flash / Claude Haiku) como fallback para intenciones no reconocidas.

Notebook Python

Reproducir todos los algoritmos con pandas / scikit-learn / mlxtend / statsmodels y cruzar resultados con la implementación JS.
